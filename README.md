# 🔄 Local transfer to UCMDB

**Скрипты UCMDB Discovery для консолидации и нормализации инфраструктурных CI/IP-данных**

`Python / Jython` · `UCMDB Discovery API` · `DNS` · `Topology Query`

</div>

> [!NOTE]
> Исторический интеграционный проект из раннего этапа работы с системами управления конфигурациями.
> Код сохранён в исходной архитектуре и рассчитан на выполнение внутри среды UCMDB Discovery, а не как самостоятельное Python-приложение.

## О проекте

Проект реализует локальную обработку и перенос данных внутри UCMDB с приведением разнородных конфигурационных единиц к единой IP-центричной модели `cc_ip_address`.

Основная задача — собрать данные из нескольких типов CI, нормализовать IP-адреса, дополнить их связанными атрибутами инфраструктуры и сформировать унифицированные объекты для дальнейшей загрузки в UCMDB.

## Что реализовано

- Консолидация данных из нескольких типов конфигурационных единиц в `cc_ip_address`.
- Нормализация IP-адресов, включая строки с несколькими адресами и диапазонами.
- Обогащение результата данными узлов, интерфейсов и сетевых сервисов.
- Определение DNS-имён и доменов.
- Формирование подсетей из IP-адреса и маски.
- Выявление повторяющихся IP-адресов и сохранение информации об источниках.
- Работа с UCMDB Topology Query и связями между CI.
- Пакетная отправка сформированных объектов в UCMDB.
- Отдельный discovery-скрипт для DNS enrichment.

## Структура

| Файл | Назначение |
| --- | --- |
| `cc_ip_address_generator_gnezdo.py` | Обработка данных из нескольких исходных типов CI и формирование унифицированных `cc_ip_address`. |
| `cc_ip_address_generator_ucmdb.py` | Ранняя версия генератора `cc_ip_address` из данных UCMDB. |
| `cc_ip_address_generator_ucmdb_v2.py` | Версия на основе UCMDB Topology Query с обработкой связанных Node, Interface и IP Service CI. |
| `ip_address_formatting.py` | Нормализация IP-адресов и разбор некоторых составных форматов и диапазонов. |
| `dns_discovery.py` | DNS resolution и обновление `authoritative_dns_name` для IP CI. |

## Технологический контекст

Код использует API и runtime UCMDB Discovery:

- `ObjectStateHolder` / `ObjectStateHolderVector`;
- UCMDB Topology Query Service;
- `Framework` API;
- `netutils`, `modeling`, `shellutils`;
- Java/UCMDB classes, доступные внутри Jython runtime;
- DNS resolution и локальные discovery-команды.

Поэтому репозиторий не содержит самостоятельного окружения запуска: соответствующие зависимости предоставляются самой платформой UCMDB.

## Статус

Проект больше не развивается и сохранён как исторический пример интеграционной задачи: преобразование разнородных инфраструктурных данных в единую модель с нормализацией, обогащением и загрузкой обратно в CMDB.
